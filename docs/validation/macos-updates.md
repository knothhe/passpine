# macOS 隔离更新安装验收

2026-10-23，在 macOS 27.0.1 / Apple Silicon arm64 上完成。移除增量更新后，重新执行六项完整包真实进程和文件系统测试并全部通过；结构化结果见 [macos-updates.results.json](macos-updates.results.json)。

## 实际验证结果

| 场景 | 结果 | 用时 | 关键证据 |
| --- | --- | --- | --- |
| 完整包安装 | 通过 | 2.9 秒 | 只请求一次完整包；真实旧应用退出前 bundle 不变，新应用完成 native 初始化确认后提交安装 |
| 下载的完整包损坏 | 通过 | 0.3 秒 | 一次完整包请求后哈希校验失败，不进入待安装、不启动安装助手，旧 bundle 不变 |
| 新版启动即退出 | 通过 | 31.3 秒 | 测试故障标记证明新版实际执行；曾换入新版，随后完整恢复旧 bundle，并重新启动旧测试应用 |
| 新版没有启动确认 | 通过 | 31.5 秒 | 在临时构建中仅去掉健康确认调用，真实 helper 等待约 30 秒后恢复并启动旧版 |
| macOS bundle 签名失效 | 通过 | 1.5 秒 | Feed 与文件哈希有效，但资源修改使 `codesign` 校验失败；未观察到新版换入，旧 bundle 完整保留并重新启动 |
| 安装前更新包被篡改 | 通过 | 0.4 秒 | 下载完成后修改缓存 ZIP；`Install` 返回 `verification`，不启动安装助手、不替换应用 |

每个场景都比较了 15 个受保护文件的完整路径集合和 SHA-256，包括虚构密码库密文、私钥、公钥与偏好设置，内容全部保持一致。成功安装与回滚后的整个 bundle 均与对应原始构建的逐文件哈希完全一致，且重新通过 `codesign --verify --deep --strict`。成功路径确实收到了生产代码的 native 初始化确认；回滚路径另验证了旧版版本号及重启进程存活。

## 隔离方式

- 所有应用、缓存、数据及 TLS 证书均位于新建的 `/private/tmp/passpine-update-verification-*`，没有执行 `make install`、浏览器注册或修改任何现有安装目标。
- 旧版和新版是实际 `client/cmd/passpine` 编译产物，使用临时版本 `99.0.0` → `99.0.1`、一次性 Ed25519 测试密钥和独立 bundle identifier。没有修改仓库版本或生产签名配置。
- 真实应用使用 `--preview --data-dir <临时目录>`，只加载自动生成的虚构密码库。预览模式跳过浏览器服务、真实全局快捷键和开机项；测试包不携带设备解锁 helper。
- `XDG_RUNTIME_DIR`、`TMPDIR`、Foundation 用户目录、GnuPG 目录和 Git 配置均隔离；没有重新定义 `HOME`，没有读取或复制真实密码库和私钥。
- 控制进程使用 loopback HTTPS 和专用临时 CA 调用正式 `update.Manager`，安装助手执行的仍是正式 `RunHelper`、包校验、macOS 原子交换、启动确认和事务回滚实现。
- `Install` 后控制进程通过 `syscall.Exec` 变成真实旧应用，保留 helper 计划记录的父 PID。验证旧应用存活时文件不变后，只结束经精确路径核对的临时 PID，让真实 helper 继续安装。
- 故障注入只存在于临时 Go overlay：新版提前退出，或省略启动确认。生产 updater 源码没有为测试改动。
- 所有进程终止前都要求命令行以本次随机隔离目录开头，不使用按名称匹配的 `pkill` 或 `killall`。

本次验证的是更新与启动链路；安装信号由测试控制器提供，未操作正式设置页中的按钮，也不将 native 初始化确认当作窗口绘制截图证据。

## 重现

在 macOS arm64 上执行：

```sh
node scripts/verify-macos-updates.mjs --run
```

脚本默认不运行，必须传入 `--run`。会构建并启动临时测试应用，两个故障场景各需等待约 30 秒。脚本会关闭自身测试进程，并输出本次隔离目录及 JSON 汇总；目录中只含测试应用和虚构数据，可用于诊断后删除。此次验收的临时应用、虚构密钥和测试证书已清理，仅保留脚本与结果记录。

## 完整包更新与通道隔离

本次脚本仅生成完整包 Feed，不包含内联更新说明或增量地址；每个场景都断言完整包只请求一次。验收脚本显式将临时应用、Host 和控制器编译为 `release` 通道，使用本轮临时测试公钥；日常 `make build` 仍为 Dev，不具备正式更新能力。

客户端单元测试另覆盖旧 schema 1 Feed 中 `notes` / `deltas` 字段的兼容读取：保留签名验证并忽略旧字段，只请求完整包；旧增量缓存不能恢复成待安装状态；缺失文件的完整包不能借用现有安装文件补齐。本轮结果替代此前的增量安装与回退验收记录。
