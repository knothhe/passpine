# 配置同步

客户端设置 → **配置同步**可连接用户自己的 Cloudflare R2 或 S3 兼容对象存储。密码库继续使用原有 Git 同步，两条通道独立。

支持同步客户端和浏览器扩展的主题风格、明暗外观、字号、语言，以及扩展的网站关联与取消关联；两端外观分别保存，不强制使用同一外观。本机路径、当前密码库、私钥、系统解锁、浏览器权限、快捷键、安全时长、开机自启和操作记录不上传。

## 同步选项

设置 → **配置同步**中的**同步选项**可配置以下内容，点击**保存同步选项**后生效：

- **同步内容**：客户端偏好与扩展偏好分别提供总开关，并可单独选择**主题与外观**、**字号**、**语言**，默认全部开启。关闭总开关会保留各项选择；未选择的内容不会上传或应用，保留本机和云端已有配置。重新开启后按最后应用的基线合并；首次启用的内容优先导入远端值，之后的同字段冲突仍需选择要保留的配置。
- **同步模式**：默认为**自动同步**；**仅手动同步**只在点击**立即同步**时与云端同步，仍可连接扩展并在本机暂存其修改。定时、启动和修改后同步设置保留，在切回自动模式后继续使用。
- **同步时间间隔**：1、5、15、30 分钟或 1 小时，默认 5 分钟。定期检查云端并合并修改。
- **启动时同步**：默认开启，应用启动后检查一次云端配置。关闭后等待设定间隔，或在启用修改后同步时由本地变更触发。
- **修改后自动同步**：默认开启，本地偏好修改后约 2 秒安排同步；关闭后等待定时检查，或点击**立即同步**手动同步。
- **同步异常提醒**：默认开启，同步失败或冲突时显示可打开同步设置的提醒。窗口隐藏时优先使用系统通知；系统不支持或拒绝通知时保留应用内提醒。相同连接的相同问题在连续重试期间只提醒一次，成功恢复后新的失败可再次提醒。提醒不包含端点、桶名、凭据或服务端响应正文。

页面将连接状态与操作、同步内容、同步行为分组展示；编辑连接时仍显示当前已保存连接。选项仅保存在本机，不上传到云端；连接前或暂停时也可设置。保存选项不会测试连接或读取系统凭据；**还原更改**可丢弃未保存的选项编辑。暂停同步会停止自动与手动同步，恢复后按已保存模式运行。旧版保存的选项自动沿用原有同步间隔与总开关，并为新增选项使用默认值。

使用细分扩展同步前，请同时更新参与同步的客户端与浏览器扩展。旧版扩展只接受完整偏好，旧版客户端也不支持仅含部分扩展字段的云端文档；混用时可能停止配置同步或提示数据格式无效。原有数据不会被自动清空，升级两端后可继续同步。

## 扩展网站关联

扩展通过 `configure` / `list` 的 `browser-associations-v1` 能力协商保存方式。支持时，网站关联和取消关联由客户端保存到独立的私有文件 `browser-associations.json`，扩展只保留按正式 / Dev 客户端、客户端数据目录及密码库身份隔离的缓存。旧客户端保存普通偏好不会覆盖此文件；此前写入 `preferences.json` 的关联记录会自动迁移，已有独立文件优先，损坏文件不会被重置覆盖。

扩展每分钟通过后台定时任务拉取一次，普通读取使用 60 秒缓存；重新打开弹窗和手动刷新也沿用这个缓存窗口。修改关联前会重新核对客户端身份，保存成功后立即更新当前浏览器缓存。浏览器休眠或限流时，定时任务可能延后。客户端暂时不可用时保留缓存，关联写入失败会反馈给用户，不会把未保存的修改当成客户端已保存。

首次连接会将原扩展本地关联导入客户端，只补入缺失的记录，客户端已有记录优先；原始本地记录保留以兼容旧客户端。取消关联以明确的 `false` 记录保存，覆盖路径推导匹配和旧关联。客户端没有此能力时继续使用原有本地逻辑，不发送新协议请求。

支持 `browser-association-operations-v1` 的客户端还会校验写入目标的存储身份，并持久记录待同步批次的操作标识。同一批次在确认丢失或扩展后台重启后重复提交时不会再次修改关联，防止旧操作覆盖其他浏览器之后的修改。操作确认记录只保存在本机，不参与云同步。缺少此能力的中间版本不会自动重放待同步批次；存在已发送批次时需更新客户端后继续保存。

关联数据随**扩展偏好**总开关进入现有加密配置同步通道，独立于主题、字号和语言的细分选项。关闭总开关或暂停云同步仍可在本机客户端保存；自动、手动及冲突处理沿用现有同步设置。不同关联逐条合并；同一关联出现不同修改时，通过现有冲突页面选择保留本机或云端状态。

同一远程 Git 密码库使用规范化的 `origin` 和根收件人策略计算身份，不同本地目录可共享关联；原有本机密码库 ID 作为旧记录别名保留。GitHub.com、GitLab.com 的标准 `git` 用户 SSH 地址可与 HTTPS 地址共用身份；其他 SSH 服务保留用户名、端口及相对用户目录 / 绝对路径的区别，不推断它们与 HTTPS 指向同一个仓库。没有可识别的远程仓库或 SSH 地址没有明确用户名时按本机密码库 ID 隔离。修改远程仓库或根收件人策略会产生新的关联身份，避免不同密码库仅因共用密钥而混用网站关联。只保存身份、条目和 hostname 组合的摘要及状态，不保存明文网址、密码或条目正文。

## 导入与导出

配置同步页提供**导入配置…**和**导出配置…**，通过本地 JSON 文件迁移同步选项及服务端点、存储桶、区域、目录前缀、路径寻址等连接参数。默认文件名为 `passpine-sync-config.json`；未配置连接时可仅导出同步选项。导出采用当前页面的选项与所选连接草稿，未编辑连接时采用当前已保存连接。连接参数不完整时先补全再导出；已有文件不会被覆盖，请选择新文件名。

文件不包含访问密钥、Session Token、OAuth 授权、系统凭据引用、同步加密口令、合并基线或密码库内容。R2 连接同样只导出对象存储参数，导入后进入**手动配置 S3**，由使用者填写自己的访问凭据与原同步空间的加密口令。

导入只更新页面草稿，不会自动连接云端、读取系统凭据或立即保存。检查后点击**保存同步选项**；文件包含连接参数时，还需补齐凭据并点击**保存并连接**。文件仅包含同步选项时保留当前连接编辑；导入文件无效、超出 64 KiB 或导入期间另有编辑时，现有草稿保持不变。文件版本及字段会严格校验，不支持把本机内部的 `config-sync.json` 直接当作导入文件。

## 手动 S3 配置

填写服务端点、存储桶、区域、目录前缀、Access Key ID、Secret Access Key，可选 Session Token 与路径寻址。R2 通常使用 `https://<account>.r2.cloudflarestorage.com`、区域 `auto` 和路径寻址；其他 S3 服务使用其实际区域与端点。端点不包含桶名、查询参数或凭据，仅支持 HTTPS；隔离本地服务可用 loopback HTTP。

“测试连接”只读取桶列表，不创建、修改或删除对象；成功仅表示当前读取权限可用，写入权限在实际同步时验证。“保存并连接”先完成候选连接的首次同步，成功后再替换已保存连接；口令错误、文档损坏或写入失败时保留原连接及编辑草稿。保存后的旧凭据清理失败会保留清理记录与警告，新连接仍然生效。已保存的同一目标可留空秘密输入以保留本机凭据；更换端点或桶需要重新填写凭据。

每个同步空间使用独立的加密口令，至少 12 个字符。在其他设备填写相同的端点、桶、前缀和加密口令即可恢复。此口令与密码库的私钥口令无关，Passpine 没有服务端恢复功能。手动与 OAuth 连接方式不改变同一空间的身份。

## Cloudflare OAuth 发行配置

发行者在 Cloudflare 注册 **Passpine 自己的** OAuth client；普通用户只需点击授权并选择可访问账号、辖区和已有桶。缺少 Client ID 时授权入口明确不可用，手动 S3 不受影响。

公开配置位于 [`client/r2config/publisher.json`](../client/r2config/publisher.json)，可通过 `PASSPINE_CF_OAUTH_CLIENT_ID` 和 `PASSPINE_CF_OAUTH_REDIRECT_URL` 显式覆盖。仓库不包含其他应用的 Client ID 或 Client Secret。当前回调地址：

```text
http://127.0.0.1:47839/oauth/callback
```

注册必须精确匹配此地址。Grant type 使用 `authorization_code` 和 `refresh_token`，Response type 使用 `code`，Token endpoint authentication 使用 `none`，PKCE 使用 `S256`。所需业务权限以已锁定版本的 [`r2connect.RequiredScopes()`](https://pkg.go.dev/github.com/knothhe/r2connect#RequiredScopes) 为准；SDK 统一请求 `offline_access`，Passpine 不另维护一份 scope 规则。

同意页如果将 **Account API Tokens Write** 放在 Sensitive scopes，需要在 Edit Permissions 中开启。账号需要具备创建专用 Account API Token 的权限。应用只派生所选桶的对象权限，不创建桶，不申请整个账号的 R2 管理权限。

Cloudflare 的 [R2 IAM 权限最多需要一分钟才能全球生效](https://developers.cloudflare.com/r2/reference/consistency/#operations-and-consistency)。新候选连接的只读探测遇到 401/403 时，会复用同一令牌退避重试，累计等待最多一分钟；可以取消，持续拒绝仍报错并保留候选连接。手动 S3 和已保存连接不使用此重试。

先用 private visibility 和发行者测试账号验证；对其他账号开放前，按 Cloudflare 要求配置应用名称、Logo、Client URL、scopes 和域名验证，再决定是否改为 public visibility。仓库开发不会自动注册 OAuth client 或更改其可见性。

参考：[OAuth 注册](https://developers.cloudflare.com/fundamentals/oauth/create-an-oauth-client/)、[OAuth 集成](https://developers.cloudflare.com/fundamentals/oauth/integrate-with-cloudflare/)、[R2 凭据派生](https://developers.cloudflare.com/r2/api/tokens/)。

## SDK 与平台构建

Cloudflare OAuth、loopback 回调、账号和存储桶 API、桶凭据派生、续期与清理由 [`github.com/knothhe/r2connect`](https://github.com/knothhe/r2connect) 统一实现，版本锁定在 `client/go.mod`。Passpine 保留自己的公开发行配置、同步空间和加密对象引擎；OAuth 与手动连接最终都使用同一套 S3 数据读写。

macOS 的 SDK Keychain 后端需要 cgo。`scripts/build-client.sh` 在执行构建工具前检查并导出 `CGO_ENABLED=1`，显式禁用 cgo 会报错停止；需要 Xcode Command Line Tools。现有 macOS Release CI 已设置 `CGO_ENABLED=1`。Windows 使用原生 Credential Manager，Linux 使用 Secret Service；不因 macOS 的构建要求改写另外两端的编译标志，也不以交叉编译结果代替系统凭据的原生验收。

授权没有返回刷新令牌时仍可保存有效桶凭据，界面会提示此授权无法静默续期，应在桶凭据到期前重新连接。SDK 清理旧 Token 或授权失败时会保留归属记录，并持续显示清理提示；不能把授权或同步成功当作旧凭据已经撤销。

SDK 元数据读取失败单独显示，保留已保存目标和编辑输入，不能降级成“未连接”后覆盖原文件。修复配置目录中的有效状态后可点击“重新读取配置”；此操作只重建读取失败的 SDK manager，不读取系统凭据，也不重建健康 manager 或丢弃其尚未持久化的旋转令牌。

已加载的 SDK 状态文件被修改、删除或变得不可读时，客户端会清空本进程的凭据读取副本并停止当前 R2 会话，保留现有 manager 中尚未保存的刷新和清理记录。请关闭其他实例并重启 Passpine 后重试；“重新读取配置”不会替换健康 manager。检查覆盖 R2 操作入口和 SDK 状态写入前，不能代替跨进程文件锁。

## 数据、安全与冲突

对象默认保存在 `passpine/settings.v1.enc`。同步文档有版本和命名空间，当前使用 `desktop.*` 与 `browser.*`；命名空间内可只包含所选字段，未知字段在读写时保留，为后续数据类型留出空间。新增数据仍需显式定义本机持久化、权限与合并规则，不能直接序列化整个应用设置或密码库。

同步内容在客户端通过 scrypt 派生密钥、AES-GCM 认证加密后上传。本机同步凭据采用单主密钥存储：macOS Keychain、Windows Credential Manager 或 Linux Secret Service 中只保存一份随机主密钥；访问密钥、OAuth access/refresh token、派生桶凭据、同步加密口令与合并基线以认证加密密文保存在应用数据目录的 `sync-secrets-v1.enc` 中。SDK 的各个逻辑 key 保持独立，所有对象操作仍经过 SDK 的凭据有效期与续期检查。Dev、正式版和不同数据目录按规范化路径隔离主密钥与密文；密文不可跨资料库搬用，系统存储不可用时不会退回明文文件。取消或拒绝系统访问后停止本次运行的自动凭据访问，用户主动连接或断开时才能重试。

旧版分散在系统凭据存储中的条目按实际使用逐项迁移，不在启动或打开设置时批量读取。只有新密文持久写入，并用系统存储真实回读的主密钥校验成功后，才清理对应旧条目；失败、取消或拒绝时保留原条目及待清理记录，不会因迁移丢掉 OAuth、候选连接或旧代 Token 的清理能力。首次迁移仍可能需要批准旧条目的访问，完成迁移后正常重启只需读取系统中的主密钥，不能据此保证 macOS 首次读取只显示一张系统弹窗。

每条逻辑凭据保持 64 KiB 上限；完整密文文件上限为 16 MiB，最多保存 4096 条有效或待清理记录，已完成删除的记录会移除，避免长期累积。

本地密文使用原子写入与跨进程锁，读取失败、版本不受支持或认证失败时不覆盖原文件、不回退读取旧条目。密文存在但主密钥缺失时不会自动生成新密钥替换。备份或恢复时必须同时考虑本机系统存储中的主密钥和密文文件；只复制密文无法解密，配置导入/导出也不包含主密钥或凭据库。断开删除对应逻辑凭据并保留其他 profile；Dev 卸载继续保留用户数据和凭据。

成功读取的凭据会在当前进程的连接会话内复用，并合并并发读取；读取失败不会缓存。没有变化的同步不再改写凭据或合并基线。真实写入、轮换和删除会使对应副本失效，下一次读取仍须从持久化存储回读校验；拒绝访问、主动重新连接或断开、外部 SDK 状态变化及退出会清除会话副本。对象操作仍逐次调用 SDK `Credentials` 检查到期与续期，缓存不会跳过这些检查。主动重试会先检查凭据库是否变化；文件未变时保留应用侧写入失败的待保存基线，避免覆盖后续编辑，只有确认发生外部变更时才丢弃旧会话的待保存副本。

macOS 当前仍使用 SDK 默认的传统 Keychain 后端，尚未接入 `LAContext` 认证复用或迁移到 Data Protection Keychain。单主密钥与进程内复用减少后续系统读取次数，不保证首次读取只有一次弹窗，也不保证固定自签证书在重构建后永久免授权。Dev 构建默认固定签名，配置入口见[版本与发布文档](versioning.md#macos-签名身份)。只在钥匙串中直接修改条目或访问控制、而不改变 SDK 状态文件时，内存副本未必即时失效；请重启或主动重新连接以重新读取。

扩展通过本机客户端同步，不接收云端凭据。扩展本地存储分别记录各客户端及同步空间的外观、语言基线和待上传修改，后台重启、离线或暂停期间的修改在恢复连接后继续发送；切换客户端或同步空间不会把另一目标的待上传设置混入新目标。

首次连接优先采用远端已有字段；之后按字段进行三方合并。不同字段的修改可合并，同字段出现不同修改会暂停同步并显示冲突，用户选择保留本机或使用远端后重试。提交使用 ETag 条件写入，避免并发上传静默覆盖。错误口令、损坏文档和未来版本不会被当作空文档覆盖。

同步按周期检查，保存本地偏好后安排合并；失败退避重试，冲突等待用户处理。暂停保留连接和远端对象；断开清理本机连接，并撤销应用创建的 R2 桶 Token 和 OAuth 授权，保留用户桶内数据。手动填写的密钥由用户管理，不自动撤销。

开启操作记录时，同步操作也写入应用数据目录的 `activity.json`，失败记录包含受控的 `errorCode` 和可用的 `httpStatus`，遵循现有保留设置。状态轮询不记录，记录中不包含端点、桶、凭据、加密口令或服务端响应正文。

## 验证范围

自动测试使用临时目录、内存凭据存储和本地 HTTP 服务，覆盖加密、S3 签名、并发条件写入、字段合并、重启基线、OAuth 回调与权限校验、凭据访问拒绝、续期与清理。不会读取真实密码库、访问真实桶或修改用户系统凭据。

真实 OAuth 验收需要发行者自己的 Client ID、隔离应用数据目录与专用测试桶；真实系统凭据授权及 Windows/Linux 原生行为需要在目标系统验证。交叉编译或本地替身测试不替代这些验收。
