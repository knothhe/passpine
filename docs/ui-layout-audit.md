# Passpine 排版与间距调研

这项工作通常叫 **UI 视觉审计**或**排版审查**。把组件边界、字号、内边距和元素间距画出来，叫**尺寸与间距标注（Redlines）**；进一步整理共同规则，则属于**设计系统审计**。

标注回答“现在是多少”，评估回答“为什么合适、哪里值得调整”。测量值不是自动评分，14px 间距不因不是 8 的倍数就成为问题。

## 检查入口与覆盖范围

继续在独立 `research/ui-layout-audit` worktree 中开发。浏览器工作台启动方式：

```sh
pnpm --dir browser run preview --port 5184
```

打开 <http://127.0.0.1:5184/?view=audit>。切换「检查界面」可检查扩展弹窗及设置页，也可直接进入 <http://127.0.0.1:5184/?view=audit&surface=options>。

- 弹窗：列表、详情、编辑、生成器、对话框、通知、锁定及未连接状态。通过原界面操作进入各页，组件树随实际 DOM 更新。
- 设置页：连接、外观与语言、快捷键、关于，以及弹出选择菜单；独立 iframe 的 390/760/1100px 视口触发真实媒体查询。
- 数据夹具：标准账号、长域名与内容、长列表、空密码库、未配置、填充失败、关联失败。切换数据场景或检查界面会重建该示例；切换语言、主题与字号保持当前编辑状态。
- 开发版扩展：在真实 popup/options 入口用 `Ctrl / ⌘ + Alt + Shift + L` 打开检查器，Escape 关闭。侧面工具不改变原弹窗尺寸，可折叠或移到顶部/底部。生产构建移除该检查器的运行代码和样式。

A、B 选择支持边缘间隔与对齐偏差。尺寸来自当前 DOM；字号、行高、内外边距来自计算样式。可滚动组件保留完整尺寸与可见裁剪区域；被移除元素会释放选择。导出的 JSON 包含布局、样式和夹具元数据，不读入账号字段值、正文或凭证。`initialConnection` 表示夹具的初始连接状态，示例内随后发生的锁定或解锁不会改变该字段。

原生 MyGo 客户端在 `client/` 目录运行：

```sh
go run ./cmd/passpine --preview --layout-audit
```

这个入口要求临时虚构密码库，拒绝 `--data-dir` 和 `--seed-test-vault`。主窗口的列表、详情、编辑、生成器、设置、回收站、初始化、锁定及确认框共用根视图装饰器；独立快速搜索窗口也接入，并单独保存测距状态。工具栏提供真实布局边界、8 DIP 网格和手动两点测距。F12 打开 MyGo 自带原生检查器，macOS `⌘⇧C` 进入元素选择；其他平台使用 `Ctrl+Shift+C`。

MyGo 自带检查器读取完整渲染树，显示内容、内边距、边框、外边距以及实际字体规格。上游检查器界面目前是 English，Passpine 增加的工具栏有中英文。`mygo_noinspector` 构建保留网格和手动测距，并明确提示自动检查器不可用。

## 可复用组件边界

| 组件 | 可复用接口 | 应用负责什么 |
| --- | --- | --- |
| [TypeScript / React](../browser/src/layout-audit/README.md) | `useLayoutAudit`、`AuditOverlay`、`measureElement`、`compareRects` | 提供检查根节点、控制面板、文案、允许检查的 portal、启用策略。 |
| [MyGo](../client/layoutaudit/README.md) | `layoutaudit.State.Wrap`、`Options`、`Labels`、`Measurement` | 每个窗口持有状态、提供翻译、启用 MyGo 原生 DevTools、选择启动方式。 |

两套实现不相互调用，也不依赖密码库。TypeScript 包只依赖 React/React DOM；Go 包只依赖 MyGo 的公开 `ui` API 和标准库。它们都可复制到其他项目继续使用，本次没有发布 npm 或独立 Go module。

两端共用的是检查方法而非像素数：浏览器测量 CSS px，原生测量逻辑 DIP。原生手动两点尺不自动推断组件间距或字号，自动元素指标交给 MyGo 自带检查器。其渲染树暂未提供公开遍历 API，因此没有通过反射访问私有状态。

DOM 组件支持同源 iframe 和显式允许的 portal。旋转或斜切元素使用轴对齐外接矩形；任意裁剪路径、圆角遮挡、重叠遮挡、Shadow DOM、跨域 iframe 和 canvas 内部内容不在自动 DOM 测量范围。这些边界不应被误判为已完成全量可访问性验证。

## 怎么判断是否合适

| 维度 | 要回答的问题 | 建议检查方式 |
| --- | --- | --- |
| 对齐 | 标题、正文、输入框是否共享有意义的边线？ | 画内容边线，区分容器边缘、文字起点和图标视觉中心。 |
| 分组 | 用户能否看出哪些内容属于同一组？ | 比较组内与组间距离，标签应明显靠近对应内容。 |
| 文字层级 | 扫一眼能否找到主要内容？ | 同时看字号、字重、颜色和位置，避免每个层级都靠放大字号区分。 |
| 密度 | 常用信息与操作是否容易找到、点击？ | 比较可见条目数、长名称截断、操作占用宽度和滚动成本。 |
| 可读性 | 小字号在实际屏幕、语言和主题下是否清楚？ | 看真实文字与背景，比较缩放状态，不能只看字号数值。 |
| 适应性 | 内容变长、窗口变窄、文字放大后是否仍可用？ | 测长名称、中英文、字号偏好、缩放、换行和滚动。 |
| 一致性 | 同类组件是否遵循相同规则？ | 比较列表与详情、多个表单字段及各类按钮，保留场景需要的差异。 |

4px 或 8px 步进可以作为团队整理间距变量的工具。紧凑弹窗、较宽设置页和桌面窗口有不同的信息密度，不要求所有页面使用同一间距。

## 浏览器弹窗的初步观察

以下为默认 100% 字号的源码值，单位是 CSS px。来源为 [style.css](../browser/src/style.css) 与 [AccountList.tsx](../browser/src/components/AccountList.tsx)。

| 对象 | 当前值 | 初步判断 |
| --- | --- | --- |
| `.popup-shell` | 380 × 460，页面 gutter 14 | 固定空间使密度与可读性需要一起评估。 |
| 搜索框 | 高度 34，字号 12.5 | 与正文大小接近，需检查长占位文字和缩放。 |
| 列表行 | 最小高度 50，行间距 2 | 紧凑且有节奏，实际高度可能随内容变化。 |
| 列表主文字 | 字号 12.5，行高 18 | 与详情主值一致，是可保留的共同规则。 |
| 文件夹与凭证标签 | 字号 10，行高 14 | 层级明确，但小字号值得单独做可读性比较。 |
| 主次文字间距 | 3 | 组内关系紧密，可与行间距和行高一起观察。 |
| 当前网站标记 | 字号 9 | 80% 偏好下为 7.2，建议优先检查是否容易辨认。 |
| 列表操作 | 点击区域 30 × 34，图标 17 或 18 | 图标大小与点击区域不同，应分别标注。 |
| 编辑表单 | 字段组间距 14，标签间距 6，输入框高 36 | 组间距离大于组内距离，关系清晰。 |
| 底部工具按钮 | 28 × 28 | 可与列表操作比较一致性及误触情况。 |
| 通知关闭按钮 | 20 × 20 | 需结合相邻目标距离复核，不能只按尺寸直接判失败。 |

### 值得进一步比较的三个问题

1. **内容左边线。** 列表文字的理论起点由列表容器 8、行边框 1、按钮内边距 7 合成 16；通用 gutter 为 14。可用标注观察这 2px 差异是否造成视觉不齐，也要区分搜索框外边缘与输入文字起点。
2. **辅助文字可读性。** 列表与详情都使用 10/14 的次级文字，这是统一的规则。可尝试与 11px 方案比较，但增加字号会影响一屏条目数和长文本截断，没有单一数值能决定好坏。
3. **操作与内容的宽度分配。** 每行四个操作占 120px 固定宽度。使用 `/?view=audit&fixture=rich` 检查长名称，并观察英文和 120% 字号时主要信息是否仍容易辨认。

这些是待比较的设计问题，不是已经确认的缺陷。CSS 注释把主文字概括为 13px，实际规则是 12.5px；审查应以生效样式和测量值为准。

## 可访问性依据与边界

- **点击目标：** WCAG 2.2 的 2.5.8 使用至少 24 × 24 CSS px 的尺寸要求，同时有间距、等效操作、行内等例外。测得小于 24 不等于已经确定不符合。见 [Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。
- **对比度：** 普通文字通常要求至少 4.5:1，大字号文字为 3:1，并有特定例外。必须结合实际背景计算，不能仅根据“灰色”或字号判断。见 [Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。
- **文字放大：** 需要能够放大到 200% 且不丢失内容和功能，可以通过受支持的浏览器机制实现，不要求应用自己的字号选项一定达到 200%。当前 80–120% 偏好的检查不等于完成这一验证。见 [Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)。
- **文字间距：** 用户覆盖行高至字号的 1.5 倍、段后间距至 2 倍、字间距至 0.12 倍、词间距至 0.16 倍时，需要保留内容与功能；不适用的语言属性有例外。这些是覆盖后的适应要求，不是默认排版必须采用的数值。见 [Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)。

本页是设计调研和测量示例，不构成完整的可访问性审计，也不因某几个尺寸符合基准就宣称整个产品符合 WCAG。

## 手工复核清单

- [ ] 以默认字号检查列表、详情、编辑器的边线、间距和主次文字层级。
- [ ] 验证标注值随界面、内容和字号变化更新，并与浏览器生效样式一致。
- [ ] 关闭标注观察正常界面，再开启标注核对差异，避免标注本身干扰判断。
- [ ] 检查简体中文与 English，确认用户条目内容不被翻译，切换语言不清空编辑输入。
- [ ] 检查 80%、100%、120% 字号及浅色、深色主题，关注小标签、按钮文字、截断与滚动。
- [ ] 使用 `fixture=rich` 检查长域名、长条目名和长内容，确认完整内容有可访问的查看途径。
- [ ] 用键盘完成选取、进入详情、返回和编辑，检查焦点可见且不被标注遮挡。
- [ ] 在设置页单独检查窄窗口、浏览器缩放和文字间距覆盖；真实扩展还需验证其实际支持的放大方式。
- [ ] 对需要调整的项保存“场景、实测值、问题、候选改动、复测结果”，区分测量事实与设计判断。

实现后的类型检查、测试、构建和浏览器实测结果以本次工作记录为准，上述复核项不会因为写进文档而自动视为通过。

## 验证方式

通用 DOM 组件覆盖缩放、裁剪、盒模型、A/B 比较、同源 iframe、portal、事件隔离和观察器清理；开发版集成验证检查器与语言切换保留编辑输入及凭证请求次数。长列表夹具验证详情有内容、编辑不重复、删除可保留。

MyGo 组件验证根视图布局保持、事件穿透、测距捕获与退出、窗口缩放、语言更新、快速搜索独立状态、无原生检查器构建的说明，以及九类真实视图的中英文渲染截图。截图命令见组件 README。

本地完整检查沿用 `bash scripts/check.sh`，另构建 Chrome/Firefox 扩展与独立预览，并核对生产产物不包含检查器运行代码。原生渲染截图和 macOS 实测不替代 Linux/Windows runner 的原生验收；本次未触发发布 CI。

本次验证结果：完整本地检查通过，浏览器 32 个测试文件、437 项测试通过；Chrome、Firefox 和独立预览构建通过，两种扩展生产包均未包含检查器运行代码和样式。浏览器实测搜索框与首个账号行的垂直间隔为 8 CSS px；设置页切换至 390px 视口后，内容宽度 354px、页面无横向溢出。macOS 实际窗口验证了 F12 组件树、Computed 盒模型及字体属性，以及两点测距与 Escape 退出。Linux 和 Windows 原生运行尚未验收。
